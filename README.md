## Publish on GitHub Pages
1. Copy the files into your repository (or a folder you intend to publish).
2. Replace `YOUR-USERNAME` in each article's canonical and Open Graph URL with the actual site hostname. If using a custom domain, use that domain instead.
3. Check internal links and adjust filenames if you change the slugs.
4. Enable GitHub Pages in the repository settings if it is not already enabled.
5. Visit the published pages and test navigation, mobile layout, and external references.

## SEO notes
- Each page has a unique title and meta description.
- The slug is represented by the HTML filename; GitHub Pages does not require a separate slug setting.
- Add a real author/byline, publication date, and update date only when accurate.
- Consider adding `sitemap.xml` and `robots.txt` for the complete site.
- Do not promise rankings or add unverified search-volume claims. Search performance depends on content quality, competition, site accessibility, links, and many other factors.
- Review official references periodically because product features and guidance can change.

The articles are original drafts intended for adaptation and editorial review before publication.
